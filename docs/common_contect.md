# TinyLands — Project Context

## 1. Технологии и концепция
- Unity 6 LTS, URP, C#, macOS, Input System.
- 3D low-poly, камера сверху под углом.
- Гекс-тайл состоит из 6 независимых сегментов.
- Один Prefab `HexTile`.

## 2. Архитектура

На `GridManager`:
- `HexGridGenerator.cs` — координаты, соседи, регистрация и проверка тайлов.
- `HexPlacementController.cs` — установка, Ghost Preview, поворот, очки, колода, завершение.
- `HexTileGenerator.cs` — конечная колода.
- `BiomeManager.cs` — поиск и пересчёт биомов.
- `TinyLandsUI.cs` — интерфейс.
- `HexPlacementIndicator.cs` — подсветка позиций.

Другие скрипты: `HexTile.cs`, `HexHoverHighlighter.cs`, `TileType.cs`, `HexTileDebugInfo.cs`, `BiomeSegment.cs`, `BiomeData.cs`.

## 3. Готовые механики (этапы 5–6)
- Типы: Grass, Forest, Water, Field, Village, Mountains, River, Lava.
- River/Lava занимают 1–3 сегмента и образуют единую систему выходов.
- Несовместимые соединения блокируют установку; проверки учитывают повороты.
- Конечная колода: 50 случайных плиток (Fisher-Yates), бонусные добавляются в конец.
- +10 за каждую новую совпавшую сторону.
- Идеальный гекс: +60 очков и +5 плиток.
- Старые совпадения повторно не оплачиваются.
- Пропуск доступен только при невозможности установки.
- Игра заканчивается после исчерпания колоды.
- Стартовое поле пустое. Первая плитка ставится только в (0,0), расходуется из колоды, но не приносит очков. Затем доступны шесть соседей.

## 4. Логика биомов — завершена
- Биом — связная область сегментов одного `TileType`, соединённых общими гранями внутри и между тайлами.
- После успешной установки выполняется полный пересчёт всех биомов.
- Очки за биомы не начисляются.
- Все 8 типов учитываются логически.
- Уровни:
    - Level 1 — 1–5 сегментов.
    - Level 2 — 6–15 сегментов.
    - Level 3 — 16+ сегментов.

Реализованы и проверены:
- `BiomeSegment.cs`, `BiomeData.cs`, `BiomeManager.cs` (BFS и полный пересчёт).
- `HexTile.GetSegmentIndexInWorldDirection(int direction)` учитывает поворот.
- `HexGridGenerator.OccupiedCells` предоставляет зарегистрированные тайлы.
- `HexPlacementController` вызывает пересчёт после установки.
- Проверены связность внутри и между тайлами, разделение типов, повороты и уровни 1–3.

Не повторять реализацию логики без конкретной причины.

## 5. Важная индексация
- Сегмент `i` образован center, vertex `i`, vertex `(i+1)%6`.
- Внутренние соседи: `(i+5)%6`, `(i+1)%6`.
- Направления соседей:
  0 (+1,0), 1 (+1,-1), 2 (0,-1),
  3 (-1,0), 4 (-1,+1), 5 (0,+1).
- Противоположное направление: `(direction+3)%6`.
- `worldDirectionAngles = {30f, 330f, 270f, 210f, 150f, 90f}`.
- Для мировых направлений использовать существующий `GetSegmentIndexInWorldDirection()`, не дублировать формулы.

## 6. Визуальное развитие биомов — этап 7

### Forest
- Подготовлены все 13 Prefab.
- Согласованы 5 постоянных схем развития L1–L3.
- Номер схемы сохраняется при повышении уровня.
- Все характеристики моделей, проверки Prefab, схемы и правила размещения хранятся отдельно.

Документация Forest:
https://github.com/Yulia-Kotlyarova/tiny-land/blob/main/docs/forest_doc.md

### Village
- Используется Kenney Retro Fantasy Kit.
- Дома собираются самостоятельно из модульных ассетов.
- Необходимо изучить модули и согласовать 5 постоянных схем развития L1–L3.
- Размеры, плотность и размещение пока не зафиксированы.

### BiomeVisualController
Предстоит спроектировать общую систему визуального развития биомов:
- получение данных биомов;
- определение типа и уровня;
- выбор и сохранение номера схемы;
- последовательное обновление визуальных объектов.

API, ответственность компонентов, хранение схем и жизненный цикл объектов необходимо согласовать до реализации.

## 8. Правила работы
- Не менять работающие игровые механики.
- Перед изменением кода изучать актуальные версии файлов и связанные скрипты на GitHub.
- Не предполагать, что локальные изменения опубликованы.
- Если файлы недоступны — попросить пользователя прислать их.
- При изменении скриптов предоставлять полные версии изменённых файлов.
- Сначала изучать ассеты и согласовывать решения, затем писать код.
- Не переходить к следующему этапу без согласования.
- Все спорные параметры обсуждать до реализации.
- Объяснять действия в Unity пошагово, учитывая, что пользователь новичок.
